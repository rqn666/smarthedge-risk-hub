### 1.3 面试题库（23 题）

**A. 原理层**

1. **like '%x%' 为什么慢？** —— B+ 树按前缀有序，左模糊直接失效 → 全表扫描；且只能字面匹配，搜"螺纹钢保证金"命不中正文写"螺纹钢的保证金"的记录。倒排索引是"词 → 文档列表"，与数据量近似解耦。
2. **IK 分词器两种模式的区别？** —— `ik_max_word` 细粒度（建索引用，召回全）；`ik_smart` 粗粒度（查询用，精度高）。本项目在 `EsIndexManager` 里分别配到 `analyzer` / `search_analyzer`。
3. **为什么不用 `spring-boot-starter-data-elasticsearch`？** —— 它默认管理的客户端版本与本地服务端 7.16.2 不一致；本项目直接锁 `elasticsearch.version = 7.16.2` + `elasticsearch-rest-high-level-client`（`pom.xml` :19-21、:77-82）。
4. **multi_match 的 best_fields / cross_fields / phrase 区别？** —— 我实测踩过坑：`best_fields` 要求**同一字段**同时命中所有词，搜"螺纹钢 保证金"时两词分处不同字段 → 返回 0 条；改 `cross_fields` 才符合"多词多字段"语义。另加一条 `PHRASE` + boost 3.0 让完整短语排前。
5. **字段权重怎么定的？** —— `weightOf()`：名称类（品种名/合约名）3 倍、代码类（合约代码/交易所名）2 倍、别名聚合字段 1.5 倍、正文 1 倍。目的是"名称匹配优先于正文提及"。
6. **`__alias` 是什么？为什么需要？** —— 字段中文名本身在 ES 里不可搜，用户搜"保证金""最后交易日"时这些词只出现在**字段名**里、值是"合约价值的6%" → 把中文别名拼成一段文本写进 `__alias` 参与检索。
7. **keyword 类型和 text 类型的区别？** —— text 分词可检索；keyword 不分词，用于精确匹配/聚合/排序（如品种代码、统一社会信用代码）。

**B. 一致性层（重点）**

1. **MySQL 和 ES 谁主谁从？** —— MySQL 是数据源，ES 是加速层。ES 全丢可从 MySQL 全量重建（`/api/es/sync/full`），反之不行。
2. **为什么必须 afterCommit 才写 ES？** —— 放事务里写，事务回滚后 ES 已写入 → "ES 有、库里没有"的脏数据。`EsWriteHelper` 用 `TransactionSynchronizationManager` 判断：在事务中就注册 `afterCommit` 回调，不在事务中就直接写。
3. **afterCommit 里进程崩了呢？** —— 这个窗口确实存在，兜底是重试表 + 全量重建接口。定位是**最终一致**，不是强一致。
4. **双写失败怎么办？会不会拖死主业务？** —— 所有 ES 异常被 `EsSyncService` 吞掉并落 `es_retry_task`（PENDING）；主业务照常返回成功。
5. **补偿时为什么不重放原文档，而要反查 MySQL？** —— 失败期间数据可能已被再改，反查拿"当前最新"；若 MySQL 里已无此条（业务删了），就改成删 ES 文档，实现自愈。
6. **重试上限到了怎么办？** —— `retry_count >= max_retry` 时状态标 `DEAD`，不再自动重试，等人工介入；`stats()` 可查各状态数量。
7. **重复补偿会不会写重？** —— 不会。ES 写入 `_id` 用业务主键，重复写即覆盖，天然幂等；DELETE 也幂等。
8. **为什么不用 Canal 监听 binlog？** —— Canal 要独立部署 + 维护位点 + 消费程序，适合多下游订阅。本项目是单体，双写 + 补偿表在自己的事务边界内就能闭环，链路短、好排查。拆微服务、多下游要感知变更时再上。
9. **为什么不用 MQ 解耦双写？** —— 同理：引入 MQ 要额外保证"消息与事务的一致性"（本地消息表/事务消息），复杂度高于当前方案能承受的收益。

**C. 降级与可用性**

1. **ES 挂了搜索接口会 500 吗？** —— 不会。`EsSearchController` catch 后返回 `503 + 明确提示`，前端据此回退到数据库分页接口。
2. **这个"降级"是自动的吗？** —— ⚠️ 措辞要收紧：**服务端没有自动 fallback 查库的代码**。搜索侧是**显式降级**（返回 503 由调用方回退），写入侧是**自动兜底**（落重试表 + 定时补偿）。另有 `es.enabled: false` 总开关一键切回数据库。
3. **为什么搜索侧不做服务端自动兜底？** —— 会让上游分不清"结果是 ES 给的还是库给的"，排序与性能预期都变了；显式失败比静默降级更可控。
4. **2~28ms 是什么口径？** —— ⚠️ 这是 **ES 服务端 `took`**（`EsDocumentService` :199 取 `response.getTook()`），不含网络与应用层组装。被追问时要主动说明口径，别把它说成"接口 RT"。
5. **ES 索引写进去能立刻搜到吗？** —— 默认 1 秒 refresh（近实时）。全量同步/双写验证场景要显式 `refresh()`（`EsDocumentService` :213），**线上高频写路径不要调**（有性能开销）。

**D. 故障排查题**

1. **线上发现"ES 和 MySQL 条数对不上"，怎么查？** —— ① `stats()` 看 PENDING/DEAD 积压；② 查 `es_retry_task` 的 `error_msg`；③ 调 `/api/es/sync/full` 全量重建对齐；④ 查日志里 `[es] 双写失败` 的 indexName。
2. **`es_retry_task` 表没建会怎样？** —— `recordRetry()` 自己再套一层 try-catch，打 error 提示"请检查 es_retry_task 表是否已创建"，不影响主业务；`compensate()` 查表失败也直接 return 不抛。

### 2.3 面试题库（22 题）

**A. AOP 基础**

1. **Spring AOP 的两种代理？本项目用哪种？** —— CGLIB。两个理由任一成立：① Boot 2.x 起 `spring.aop.proxy-target-class` 默认 true；② 被切的 Controller 都不实现接口，即使 JDK 模式 Spring 也会退化成 CGLIB。有运行时证据（`OperLogProxyTest`，代理类名 `...$$EnhancerBySpringCGLIB$$...`）。
2. **JDK 动态代理和 CGLIB 的区别与限制？** —— JDK 要求目标类实现接口，代理类与目标类是兄弟关系，只能代接口方法；CGLIB 生成子类，不要求接口，但 **final 类 / final 方法 / private 方法代理不了**。对本项目的含义：加 `@OperLog` 的方法不能是 final/private，否则注解静默失效。
3. **依赖里有 aspectjweaver，是 AspectJ 静态织入吗？** —— 不是。aspectjweaver 只提供 `@Aspect` 注解与切点表达式的**解析**，真正织入是 Spring AOP 运行时用 CGLIB 生成子类。真 AspectJ 织入要开 LTW 或编译期织入，本项目都没开。（依赖树里也没有独立 cglib jar —— Spring 5 已把 CGLIB 重打包进 spring-core。）
4. **为什么用 @Around 而不是 @Before + @AfterReturning + @AfterThrowing？** —— 耗时/正常返回/异常三种状态要在同一处算完；三个通知拼的话开始时间只能存成员变量，切面单例 → 并发串号。@Around 用局部变量。
5. **切点表达式 `@annotation(operLog)` 的含义？** —— 匹配所有被 `@OperLog` 标注的方法，并把注解实例注入方法参数。比 `execution(* com.ape..*Controller.*(..))` 更精确（只有声明的才记）。

**B. 设计取舍**

1. **为什么不用 Filter 或 HandlerInterceptor？** —— Filter 只有 URL 和请求头，拿不到"这是哪个模块的什么操作"；拦截器能到 Controller 方法但拿不到返回值与具体异常。注解 + 切面可以在**方法级声明语义**（module/action）。
2. **为什么日志要异步落库？** —— 一次 insert 几毫秒但量极大（每个写操作一条）；放业务线程白等一个 RTT，放 Tomcat 工作线程会在大批量操作时挤占请求处理能力。
3. **队列满了怎么办？** —— `CallerRunsPolicy`：退回业务线程同步写。日志可以慢，但不能出现"操作发生了却没记录"的空洞。
4. **为什么线程池 core 只给 2、队列给 500？** —— 日志任务是"短耗时、高吞吐"型，靠队列削峰即可；与 AI 线程池（长耗时、低并发）取向正好相反。
5. **关闭时会不会丢最后一批日志？** —— `waitForTasksToCompleteOnShutdown(true)` + `awaitTerminationSeconds(10)` 等 10 秒收尾。
6. **`@Async` 不生效的三个常见原因？** —— ① 同类内部调用（`this.xxx()`）不走代理；② 没配线程池 Bean 或没加 `@EnableAsync`；③ 方法不是 public 或返回值不是 void/Future。本项目把 `saveAsync` 单独放在 `OperationLogService`，切面**注入 Bean** 调用，就是为了避开 ①。
7. **`@EnableAsync` 加在哪？** —— `OperLogAsyncConfig`（:22）和 `AiAsyncConfig`（:23）各有一个。

**C. 健壮性**

1. **业务抛异常时日志怎么记？** —— catch 里记 `success=0` + `e.getClass().getSimpleName() + ": " + e.getMessage()`，然后**必须 `throw e`** 抛回。吞掉的话前端会收到"成功"但实际失败 —— 这是 AOP 最容易埋的雷。
2. **日志写库失败会让业务失败吗？** —— 不会。`saveAsync` 整段 try-catch 只打 warn，异常留在自己的线程里。
3. **怎么证明"日志失败不影响业务"？** —— `verify-operlog.sh` D 组：把 `sys_oper_log` 改名让写入必然失败 → 业务接口仍返回 `success:true`，随后表自动还原。
4. **IP 直接 `getRemoteAddr()` 有什么问题？** —— 应用挂在 Nginx 后拿到的是代理 IP（所有人都是 127.0.0.1），审计就废了。要优先读 `X-Forwarded-For` 的第一个 IP。
5. **怎么证明 IP 取的是真实客户端？** —— `verify-operlog.sh` 用**伪造的 X-Forwarded-For 头**（203.0.113.77）发请求，断言库里记到的是这个值。
6. **参数里有文件流/大对象会怎样？** —— `paramsToJson` 跳过 ServletRequest/Response/InputStream/OutputStream/MultipartFile；整体 try-catch；超过 2000 字截断。
7. **敏感字段怎么办？** —— ⚠️ **当前源码没有开关**：`@OperLog` 只有 `module` / `action` 两个属性，没有 `recordParams`。被问到要如实说"目前只按整段参数记录 + 截断，敏感字段的处理是后续改造点（可以加注解属性或做脱敏过滤器）"。**不要说"我留了 recordParams 开关"，源码里没有。**
8. **非 Web 场景（定时任务）会怎样？** —— `currentRequest()` catch 后返回 null，IP 记 null、username 记 `anonymous`，不会 NPE。

**D. 扩展题**

1. **为什么存的是方法名而不是 URI？** —— `pjp.getSignature().getDeclaringType().getSimpleName() + "." + getName()`，形如 `FuturesContractTextController.insertText`，重构改类名能跟着变，比 URL 稳定。
2. **日志量再涨十倍怎么优化？** —— ① 只记写操作（现状如此，8 个写接口）；② 批量 insert（攒批 100 条）；③ 落 ES/ClickHouse 做检索；④ 冷热分离归档 `sys_oper_log`。

### 3.3 面试题库（26 题）

**A. 为什么 RAG**

1. **为什么不直接让大模型答？** —— 模型不知道公司制度，裸答就是编。RAG 把制度片段喂给它，答案有据可依。
2. **微调（Fine-tune）和 RAG 怎么选？** —— 知识类问答、内容频繁变、要溯源 → RAG（改文档即生效、能给出处）；改变说话风格/固定输出格式 → 微调。且微调成本高、更新难。
3. **为什么不把整篇文档塞进 prompt？** —— 15 份约 4.9 万字远超上下文预算，且无关内容会稀释注意力、拉高延迟；切块检索只送最相关的 5 段。

**B. 切分**

1. **为什么按 500 字切、重叠 80 字？** —— 500 字是"语义完整"与"检索精度"的折中；重叠防止关键句正好跨块边界，两边都不完整。`chunk-overlap: 80`（= 16%）。
2. **切分时为什么优先在段落/句子边界断？** —— 硬切会把"保证金比例为合约价值的6%"腰斩成两块，都检索不到 —— 这是分块最常见的翻车方式。所以 `TextChunker` 是"段落 → 句子 → 硬切"三级回退，且要求至少填满窗口的 60%（`MIN_FILL_RATIO`）。
3. **PDF 抽出来的文字有什么坑？** —— 按视觉行换行，一句话常被折成两行。而分块器把 `\n` 视为句子边界 → 会切出"加收 2"这种半句话。所以 `normalize()` 要还原：行尾是句末标点则保留换行，中文折行直接拼接，含英文数字的折行换空格（避免把单词粘住）。
4. **重叠会不会导致同一内容被检索多次？** —— 会，但这是可接受的代价；`searchAsToolResult` 里用 `sources` 去重文档名，`chunkIndex` 能让模型/用户看出是哪一段。
5. **分块器死循环风险怎么防的？** —— 每轮 `start` 必须严格前进：回退重叠后若 `next <= start` 就跳到窗口末尾；再兜一层 `start + 1`。
6. **改分块参数后怎么办？** —— `reindex(docId)`：原始文件已落盘（`saveToDisk`），不用重传，直接 `deleteChunks` + 重跑。
7. **为什么不把 token 数当切分单位？** —— 本项目是中文为主 + 本地模型，按字符数够用且实现简单；严格来说按 token 更准，是后续优化点。

**C. 向量与检索**

1. **bge-m3 的向量维度？为什么 1024？** —— 实测 1024 维，与 `pgvector` 表的 `vector(1024)` 必须一致（`EmbeddingClient` 里做了维度校验，不一致直接抛错并提示"请统一后再重建向量"）。
2. **余弦相似度 / 内积 / 欧氏距离怎么选？** —— 文本语义检索常用余弦（只关方向不关长度）；这里用 `<=>`（余弦距离），`相似度 = 1 - 距离`。索引 HNSW。
3. **相似度阈值 0.45 怎么定的？** —— 实测 bge-m3 对相关片段 0.5~0.75、无关 < 0.3，阈值卡 0.45；太高会"检索到却被过滤"，太低会灌无关内容造成幻觉。
4. **阈值过滤为什么放 SQL 里而不是查回来再过滤？** —— 放 SQL 里（LIMIT 之前）避免把低于阈值的片段捞回来再丢掉，省 IO 也保证 Top-K 是真的 Top-K。
5. **为什么用 pgvector 不用 Milvus / ES 向量检索？** —— 数据量是几百到几千个分块，HNSW 完全够；PostgreSQL 一个容器同时管元数据和向量，省一个中间件。到千万级再上专用向量库。
6. **为什么用批量 `/api/embed` 不用老的 `/api/embeddings`？** —— 老接口一次只吃一条，200 块要发 200 次 HTTP；批量接口一次带一批（`batch-size: 8`），实测快一个数量级。需要 Ollama 0.1.26+。
7. **`PgVectorStore` 为什么不注册成 Spring Bean？** —— ⚠️ 踩过的真实坑：只要容器里有 `DataSource` Bean，`DataSourceAutoConfiguration`（带 `@ConditionalOnMissingBean(DataSource.class)`）就整体退让，MySQL/MyBatis-Plus 的数据源失效、项目起不来。所以连接池只作为组件私有字段。
8. **向量库挂了会怎样？** —— `init()` 失败只打 WARN 不阻塞启动；`search()` 里 `isAvailable()` 为 false 直接返回空，`KnowledgeService.search()` 再兜一层 try-catch 降级为空结果，对话照常（退化为普通对话）。
9. **怎么知道向量库是好的、里面有多少数据？** —— `PgVectorStore.stats()` → `GET /api/ai/kb/status` 实时回显 documents / chunks / dim / embeddingModel / topK / minScore。
10. **分块写入为什么用手写事务不用 `@Transactional`？** —— 这里的连接池是组件私有的 HikariDataSource，不走 Spring 的 `DataSourceTransactionManager`；所以手动 `setAutoCommit(false)` + 批处理 + `commit()`，失败 rollback，避免"文档一半分块可检索"的半成品。

**D. 流式与体验**

1. **为什么要 SSE 流式？** —— 本地 7B 生成一段回答要几十秒，一次性返回用户盯白屏。逐 token 推送，体感接近打字机。
2. **为什么不能"全程流式"？** —— OpenAI tools 协议要先拿到**完整** tool_calls 才能执行，"边流边调"做不到。所以链路切成两段：工具阶段非流式 + 生成阶段流式。
3. **生成阶段为什么必须摘掉工具定义？** —— 实测不摘的话模型有一定概率再发起一轮工具调用，又走一遍非流式请求，用户多等几十秒还看不到字。
4. **`stream-tool-rounds` 为什么单独配成 1？** —— 不能沿用 `max-tool-rounds - 1`：那样第 2 轮还会走一次非流式判断（实测多等约 50s，用户全程看不到字），流式就失去意义了。
5. **SseEmitter 超时怎么定的？** —— `readTimeoutSeconds(180) * 2 = 360s`。本地 7B 单轮推理就可能几十秒，默认超时会在出答案前被容器掐断。
6. **流式路径怎么防止伪造的「参考：《不存在文档》」漏出去？** —— 来源标注总在结尾，所以先扣住最后 24 个字符不发，收尾时过 `sanitizeCitation()` 再补推（`ChatService` :188-209）。

### 4.3 面试题库（24 题）

**A. 安全设计（核心考点）**

1. **为什么让 AI 做写操作要特别小心？** —— 写错的数据会直接进业务库且影响下游测算（保证金录错→风险算错）。所以这是全项目唯一带写操作的 AI 能力，设了三道闸门。
2. **"模型跳过预览直接写库"怎么防？** —— **服务端令牌机制**：`save` 只认 `pending` 里存在的 token，没经过 preview 就没有 token。不靠提示词约束模型自觉，靠机制。安全上叫"不信任边界外的输入"。
3. **为什么 save 的字段不从模型参数取，而从服务端缓存取？** —— 两个目的：① 保证"用户确认的字段"与"实际入库字段"严格一致 —— 7B 模型抄 14 个字段出错率不低；② 让"跳过预览"在服务端不可能。
4. **令牌为什么一次性？** —— `pending.remove(token)` 用掉即删，防重复提交造成重复数据；伪造/重复 token 一律拒绝。
5. **令牌 10 分钟过期怎么实现的？** —— `TOKEN_TTL_MS` + `purgeExpired()` 在每次 save 前顺手清理。
6. **为什么令牌存内存（ConcurrentHashMap）不存 Redis？** —— 单体部署、10 分钟 TTL、量小，够用且零依赖。要上集群或量大再换 Redis，接口不用动。
7. **为什么要做字典校验？** —— ① 防脏数据；② **必需** —— 底层 `insertText` 依赖品种/交易所的关联 id，匹配不上会失败。
8. **校验不通过怎么引导用户？** —— 返回 `missingRequired` + `dictErrors`，并把系统里已有的可选值列出来（`availableVarieties()` / `availableExchanges()`），让模型引导用户修正而不是瞎猜。
9. **`dryRun` 默认值为什么是 true？** —— 默认落在"安全"那一侧：不传就只预览不写库。

**B. 框架实现**

1. **工具是怎么注册的？** —— 自定义 `@Tool` 注解标记方法；`ToolRegistry implements BeanPostProcessor`，在 `postProcessAfterInitialization` 扫每个 Bean 的方法，有注解就注册进 `ConcurrentHashMap`。
2. **为什么用 BeanPostProcessor 而不是包扫描？** —— 拿到的就是 Spring **代理对象**，AOP 依然生效；包扫描拿到的是 Class，调用时绕过了代理。
3. **工具描述怎么发给模型的？** —— `ToolExecutor.asToolDefs()` 转成 OpenAI tools 协议的 `function` 定义（name/description/parameters，参数类型统一为 string），`LlmClient.callChat()` 拼进请求体的 `tools` 字段，`tool_choice: auto`。
4. **为什么参数类型统一成 string？** —— 模型给的本来就是文本；由 `ToolExecutor.convert()` 按 Java 目标类型转换，简单可控。
5. **参数名怎么拿到的？** —— `java.lang.reflect.Parameter.getName()`。**前提是编译保留参数名** —— `pom.xml` 里 `maven-compiler-plugin` 配了 `<parameters>true</parameters>`，否则拿到 `arg0/arg1`，`@ToolParam` 机制直接失效。这是个很容易踩的坑。
6. **自定义框架的两种 tool 模式是什么？** —— `prompt` 模式：把工具清单拼进 system 提示词，要求模型输出一行 JSON `{"tool":"x","args":{...}}`，后端解析（给不支持原生 tools 的 deepseek-r1 用）；`native` 模式：走标准 OpenAI tools 协议（qwen2.5）。由 `ai.llm.tool-mode` 切换。
7. **`prompt` 模式怎么防模型自造工具结果？** —— `parsePromptReply()` 里发现 `result` 字段直接丢弃并打 warn（防幻觉），结果必须由系统回灌。
8. **工具执行抛异常怎么办？** —— `ToolExecutor` 兜成可读文本（"错误：调用工具 X 失败（原因），请检查参数后重试"）回灌给模型，让它自己改参数重试，而不是直接 500。
9. **多轮工具调用怎么控制？** —— `max-tool-rounds: 3`；到上限后不再给 tools，追一条"请立即基于现有信息给出最终回答"，并置 `hitRoundLimit = true`。

**C. 模型相关（诚实说局限）**

1. **本地 7B 模型有哪些已知不可靠行为？** —— ① 偶发把 tool_calls **吐成文本**（`parseLeakedToolCall` 兜底，且要求 name 命中本次下发的工具名）；② 会**编字段**（工具没返回的用先验知识补，实测把郑州商品交易所答成上海期货交易所）；③ 会**编文档来源**（硬加"参考：《不存在的文档》"，服务端 `sanitizeCitation` 兜底）。
2. **为什么选 qwen2.5:7b 而不是 deepseek-r1？** —— r1 实测不支持原生 tools（返回 `tool_calls: NONE`），要用得切 prompt 模式；qwen2.5 支持原生 Function Calling 且人设服从度好。配置注释里写明了。
3. **温度为什么设 0.3？** —— 业务数据抽取要稳，不要发挥。
4. **怎么保证 AI 录的数据也能被搜到？** —— 走的是和普通业务一样的 `insertText`，ES 双写挂在它的事务提交后 → 自动同步；ES 挂了走重试表，最终能搜到。**这条链路是闭环的**。
5. **AI 保存成功后为什么返回里不写"已同步到 ES"？** —— 因为双写是事务提交后异步执行的，ES 不可用时只入重试队列，工具层无法断言同步结果。AI 的工具返回必须是可验证的事实，不能过度承诺（源码注释 :147-148 专门写了这条）。
6. **如果模型把一个字段抽错了，用户没看出来就确认了呢？** —— 有兜底但确实存在这个风险。缓解手段：字典校验拦住"不存在的品种/交易所"；人工确认回显全部 14 个字段；后续可以加"关键字段（保证金、交易单位）格式强校验 + 高亮提示"。

## 5. 支撑层：自研 Function Calling 框架（AI 两条功能共用，必被追问）

**一句话**：没有直接用 Spring AI，自研了一套轻量的 Function Calling 框架 ——  
`@Tool` 注解标记方法 → `BeanPostProcessor` 启动扫描注册进 `ToolRegistry` → 对话时把工具清单按 OpenAI tools 协议发给 Ollama → 模型返回 `tool_calls` → `ToolExecutor` 反射执行 → 结果作为 `OBSERVATION` 回灌 → 模型基于真实数据作答。

| 组件                   | 文件                                | 职责                                                                                                                                                                          |
| -------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@Tool`              | `ai/tool/Tool.java`               | `name()` + `description()`                                                                                                                                                  |
| `@ToolParam`         | `ai/tool/ToolParam.java`          | `value()`（描述）+ `required()`                                                                                                                                                 |
| `ToolRegistry`       | `ai/tool/ToolRegistry.java`       | BeanPostProcessor 扫描注册；重名抛异常；`ToolMeta` 存 method/bean/params/required                                                                                                       |
| `ToolExecutor`       | `ai/tool/ToolExecutor.java`       | 反射调用 + 类型转换 + 异常兜底 + `asToolDefs()`                                                                                                                                         |
| `LlmClient`          | `ai/client/LlmClient.java`        | chat / chatStream / 两种 tool 模式 / 漏 tool_calls 兜底                                                                                                                            |
| `ChatService`        | `ai/chat/ChatService.java`        | 多轮循环编排、流式两阶段、引用兜底                                                                                                                                                           |
| `SystemPromptLoader` | `ai/chat/SystemPromptLoader.java` | 读 `prompt/system-prompt.txt`，支持热加载                                                                                                                                          |
| 已注册 6 个工具            | `ai/tool/impl/*`                  | `queryFuturesContractSpec`、`queryFuturesContract`、`querySpotProduct`、`searchKnowledgeBase`、`previewFuturesContractText`、`saveFuturesContractText`（`GET /api/ai/tools` 实时可查） |

**追问应答：**

- **Q：为什么不用 Spring AI？** —— 调研过，当时它主要面向 Spring Boot 3.x / JDK 17，而本项目是 Boot 2.7 + JDK 8；另外我要控制"工具怎么暴露给模型"的细节，就自己实现了轻量的一套。
- **Q：模型自己写 SQL 吗？** —— 不写。工具方法的入参就是白名单条件，模型只能"选工具 + 填参数"；让它生成 SQL 既有注入风险，执行计划也不可控。
- **Q：模型能用任意条件查库吗？** —— ⚠️ **不能，这是重要边界**：能用的条件 = 工具方法签名上预定义的那些参数。现状每个查询工具就 1 个字符串参数；**不支持范围比较（> < between）、不支持聚合/排序**，结果上限 `MAX_ROWS=10`，分页参数没暴露。
- **Q：那"保证金大于 10% 的品种有哪些"怎么支持？** —— 加一个工具方法，把阈值和比较符作为参数，SQL 在服务端拼 —— 条件仍由我定义，模型只负责填数字。
- **Q：为什么不用 ES 做这些查询？** —— 这里要的是"命中即精确"的条件过滤，MySQL 走索引更快更简单；ES 负责中文全文检索与分词。两者分工不互相替代。
