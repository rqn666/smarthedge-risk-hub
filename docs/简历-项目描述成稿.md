## 1. 成稿

### 大宗商品套期保值风险管控平台

**• 项目背景**：面向大宗商品套期保值业务的后台经营管理系统，服务于风控、交易运营与采购人员，覆盖**期货/期权合约档案与合约条款、现货商品、交易品种与交易所字典、供应商与供应分类**等基础数据的统一管理，并内置 AI 制度知识库问答与合约文本自动解析两项智能能力。

**• 技术选型**：Spring Boot 2.7.15、Spring MVC、MyBatis-Plus 3.5.1、MySQL 8、Elasticsearch 7.16 + IK 中文分词、PostgreSQL + pgvector、Spring AOP、Apache PDFBox、Ollama 本地大模型。

**• 负责模块**：独立负责期货/期权合约档案、合约条款、供应商三大核心模块的设计、开发与单元测试；主导 ES 全文检索、AOP 操作日志、AI 知识库问答与合约文本自动解析四项能力的落地。

**• 海量数据检索性能优化**：由于业务数据量增长后 MySQL 模糊查询命中不了索引、只支持字段前缀匹配，全表扫描导致检索耗时高；引入 Elasticsearch 7.16 + IK 中文分词器重构检索链路，采用事务提交后双写方案保证 MySQL 与 ES 数据一致，写入失败落重试表由定时任务补偿；搜索响应从数据库全表扫描降至 2~28ms，ES 不可用时搜索接口返回 503 触发降级、业务写入零影响，保障服务可用性。

**• 持久层开发与多表关联查询**：单表 CRUD 基于 MyBatis-Plus 3.5.1 的 BaseMapper 与 Lambda 条件构造器实现；多表关联查询与模糊查询采用注解式 SQL 开发，配合 IPage 与 MP 分页插件实现自动分页，解决联表数据组装与分页一致性问题。

**• 注解式操作日志**：由于业务代码里到处手写日志、易漏记且侵入主流程；基于 Spring AOP + 自定义 @OperLog 注解实现操作留痕，业务方法只需声明所属模块与动作，由环绕通知统一采集方法名、请求参数、客户端 IP、耗时与执行结果；日志通过 @Async 独立线程池异步落库，与主业务逻辑解耦，保存失败只打印告警，日志入库异常时业务接口仍能正常响应。

**• AI 制度问答（面向风控与交易运营人员的制度查询场景）**：套保相关的交易、风控、交割、核算制度分散在十几份文档中，员工查一条规则要逐份翻找、还容易翻到过期版本；将 15 份套保制度文档（约 4.9 万字）解析后按 500 字切分、相邻分块保留重叠，经 bge-m3 向量化（1024 维）存入 PostgreSQL + pgvector；用户用自然语言直接提问，系统先做语义检索召回 Top-5 相关片段，再连同问题交给本地 Ollama 大模型生成答案，答案标注来源文档与分块序号、并支持 SSE 流式逐字返回 —— 把"翻文档找制度"变成"提问即得带出处的答案"，同时约束模型只依据召回片段作答，避免凭空编造。

**• AI 合约文本解析入库（面向合约档案录入环节）**：期货/期权合约条款含品种、交易所、交易单位、保证金比例、涨跌停板、最后交易日等十余个结构化字段，人工逐条录入既繁琐又易错，而字段录错会直接导致后续风险测算失真；改为把合约原文发给本地大模型，由 Function Calling 驱动模型自动抽取字段并调用入库工具：写入拆成"预览 + 确认"两步 —— 先回显解析结果并做品种、交易所字典校验，再凭服务端下发的一次性令牌落库（令牌伪造或重复使用一律拒绝），校验不通过的字段返回错误提示交由人工复核 —— 由 AI 承担机械的字段抽取，同时保留人工确认这道闸门，保证入库数据准确、可追溯。

**被追问"文档为什么是你自己整理的、不是公司真实制度"**：

> 项目里没有现成的电子版制度文档，纸质文件和零散的电子稿都不适合直接做语料。

## 1.2 这两条为什么原来"看不出在干啥"（改写公式）

原来的写法是**从技术动作起手**的：

> "将 15 份套保制度文档解析后按 500 字切分（相邻块保留重叠），经 bge-m3 向量化存入 pgvector……"

问题：读完只知道**怎么做的**，不知道**给谁用的、解决什么麻烦**。读者（HR / 面试官）第一眼要的是"这东西为什么值得做"，
技术细节是第二眼才看的。所以简历每条都按同一个公式写：

> **面向谁 / 什么场景**（有的加业务领域）→ **原来怎么难受**（1 句具体痛点）→ **我用了什么技术**（机制讲清楚）→ **现在变成什么样 + 边界**

对照一下：

| | 原来（模糊） | 现在（清晰） |
|---|---|---|
| 制度问答 | 开头就是"文档解析→切分→向量化"，看不出给谁用 | 先说"风控/交易运营人员查制度要逐份翻找、易翻到过期版本"，再说检索→生成→溯源 |
| "支持流式输出" | 一个孤立的技术名词 | 落到体验："逐字返回"，承接"提问即得答案" |
| 合约解析 | 写"对返回结果做校验"——校什么、错了怎么办都没说 | 说清"校验品种/交易所字典，不通过就报错交人工复核" |
| "入库接口" | 读者不知道写进去会怎样 | 点明业务后果："录错保证金比例会导致后续风险测算失真" |

**自查方法**：把每条的**第一句**单独拎出来读。如果第一句是"使用了 XX 技术 / 将 XX 做了 XX"，
那就还是模糊的；如果第一句能回答"这功能是给谁解决什么麻烦的"，就合格了。

## 2. ⚠️ 三处不能照抄（必读）

### ① 「接入 Spring AI」→ 必须改成「自研 Function Calling 框架」

**实情**：`pom.xml` 里**没有 `spring-ai` 依赖**。项目里是一套自己写的类 Spring AI 的 tool-calling 框架
（`ai/tool/` 下的 `@Tool` 注解 + `ToolRegistry` 工具注册表 + `ChatService.chatWithTrace()` 多轮循环 + `ToolExecutor` 反射执行）。
注意：源码里**没有** `ToolCallingAssistant` 这个类（那是别的项目的叫法），被追问要指 `ChatService`。

**为什么反而更好**：面试官听到"自研框架"比"用了 Spring AI"兴趣大得多，而且被追问
"框架怎么注册工具的""怎么把工具描述发给模型的"你都答得上来（源码在手）。

**如果面试官问"为什么不用 Spring AI"**：
> 我调研过 Spring AI，当时它主要面向 Spring Boot 3.x / JDK 17，而我的项目是 Spring Boot 2.7 + JDK 8；
> 另外我需要控制"工具怎么暴露给模型"的细节，就自己实现了一套轻量的：
> 用 `@Tool` 注解标注方法、启动时扫描注册到 `ToolRegistry`、把工具描述拼进请求，
> 模型返回 `tool_calls` 后由 `ToolExecutor` 反射执行、把结果回灌进对话循环。

### ② 「ES 不可用时自动降级数据库查询」→ 措辞要收紧

**实情**：`EsSearchController` 捕获异常后返回的是
`503 + 「ES 搜索不可用，请降级走数据库查询」` —— **降级动作是调用方做的，服务端没有自动 fallback 查库的代码**。

**改成这样说**（已在成稿里改好）：
> ES 不可用时搜索接口返回 503 触发降级、业务写入零影响。

**如果面试官追问"那你的降级是自动的吗"**：
> 搜索侧是**显式降级**：接口返回 503 并给出明确提示，由调用方（前端或上游服务）回退到数据库查询，
> 而不是服务端悄悄兜底 —— 因为服务端兜底会让上游分不清"结果是 ES 给的还是库给的"，排序和性能预期都变了。
> 写入侧是**自动兜底**：双写全部 try-catch，ES 挂了就落 `es_retry_task` 表（PENDING），
> 定时任务补偿，实测重启 ES 后能补成 SUCCESS。另外还有 `es.enabled: false` 总开关可以一键切回数据库。

### ③ 技术选型**不能**写 Redis / Spring Cloud / RocketMQ

**实情**：本项目的依赖只有——
`spring-boot-starter-web / validation / aop`、`mybatis-plus-boot-starter`、`mysql-connector-java`、
`postgresql`、`elasticsearch-rest-high-level-client`、`pdfbox`、`lombok`、`jsqlparser`。

**没有** Redis、Redisson、Spring Cloud、Nacos、RocketMQ、Shiro、JWT、Knife4j。
（那些是电商商城、campus-lost-cloud、hedgcopilot 这几个项目的技术栈，**混写会被问穿**。）

## 4. 备选标题

| 标题 | 一眼能看出什么 | 适用 |

| **大宗商品套期保值风险管控平台**（推荐） | 领域（大宗商品）+ 核心业务（套保）+ 系统定位（风控） | 投风控/交易/金融科技岗 |

**如果面试官问"你这个平台管控什么风险"**：
> 主要管的是套期保值业务里的**基础数据准确性与可用性风险**：
> 合约档案和条款（保证金、涨跌停板、最后交易日规则这些）是后续风控计算的输入，
> 录错一个字风险就算错，所以我做了两件事 —— 一是合约文本用 AI 辅助录入但**必须人工确认才落库**，
> 二是全量数据接 ES 保证能快速检索核验。指标计算模块不在我负责范围内。
